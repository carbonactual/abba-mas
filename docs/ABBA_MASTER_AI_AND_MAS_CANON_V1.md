# ABBA Master AI / ABBA MAS Canon v1

## Canonical identity

**ABBA = ABBA Master AI.** `Abba` and `AA` are aliases when used to refer to the ecosystem master intelligence. They do not define separate intelligences.

**ABBA MAS = ABBA capability fabric.** MAS provides capabilities to ABBA Master AI: tools, skills, workers, agents, adapters, workflows, integrations, command/routing, execution and proof mechanisms.

## Non-equivalence

- ABBA Master AI is not a product-specific chatbot.
- ABBA MAS is not a second sovereign AI.
- Capability does not imply authority.
- Intelligence does not imply sovereignty.
- Execution does not imply permission.
- SEAL remains the governed authority mechanism.

## Canonical flow

Human / authorized intent
→ ABBA Master AI
→ ABBA MAS capability selection
→ authority / SEAL check where required
→ execution
→ Proof / Pulse
→ Actual
→ Continuum / learning

## Ecosystem boundary

ABBA Master AI consumes Carbon Actual Core, Foundation and Floor. ABBA MAS must reuse shared capabilities instead of creating competing identity, authority, ledger, value or governance primitives.

## Repository rule

`carbonactual/abba` is the canonical ABBA Master AI candidate.
`carbonactual/abba-mas` is the canonical ABBA MAS capability candidate.
Other ABBA-named repositories are classified as mirrors, organization copies, automation subsystems, product adapters, experiments or historical sources until comparative audit proves otherwise.
